# Week 1 – Introduction To Programming

# What I Learned
We kicked things off with the basics: what a program actually is and why we use Python.
We looked at how the computer interprets our instructions and set up our coding environment.
I also learned about expressions and those annoying (but helpful) error messages that pop up when you miss a bracket.

# Practical Work
Set up my IDE and finally got "Hello World" to show up on the screen.
Played around with basic math in the Python shell to see how it handles logic.

# Reflection
Honestly, it’s a bit intimidating at first, but seeing the computer actually do what I told it to do—even just printing a sentence—was a huge win. I’m starting to see that errors aren't failures; they’re just the computer being literal.

# Week 2 – Variables & Types

# What I Learned
This week was all about data. I learned that Python isn't just a calculator; it can store information using variables.
We covered Integers, Floats (decimals), and Strings (text), and how to switch between them using type casting.

# Practical Work
Created variables to store names and ages, then used basic math to calculate things like "years until retirement."
Practiced turning string input into numbers so I could actually use them for calculations.

# Reflection
It’s like learning the "nouns" of the language. Once I figured out that 10 and "10" are treated completely differently by Python, things started clicking.

# Week 3 – Control Statements

# What I Learned
Things got interesting here. I learned how to make my programs "think" using if, elif, and else statements.
We also touched on comparison operators like == and !=. 
This is also where I started using loops to keep code running without repeating myself.

# Practical Work
Built a program that asks for a user's age and tells them if they’re old enough to drive.
Wrote a loop that counted down from 10—simple, but it felt like building a real tool.

# Reflection
I love the logic of this. It’s like a "choose your own adventure" book but for data. Indentation tripped me up a few times, but I’m getting used to Python’s strictness about spacing.

# Week 4 – Functions

# What I Learned
I learned how to wrap my code into "packages" called functions.
Instead of writing the same 10 lines of code over and over, I can just define it once and call it whenever I need it.
We also talked about passing information into functions (arguments) and getting results back (returns).

# Practical Work
I wrote a function that calculates a tip on a bill so I don't have to do the math myself.
Practiced "returning" values instead of just printing them, which makes the code much more flexible.

# Reflection
Functions make my scripts look so much cleaner. It feels less like a long list of chores and more like a well-organized toolbox.

# Week 5 – Scripts & Modules

# What I Learned
We moved out of the interactive shell and started writing proper .py scripts.
I learned how to run these from the terminal and how to "borrow" pre-written code by importing modules like math or random.

# Practical Work
Saved my code into files and learned how to run them through the command line.
Used import random to make a simple "dice roll" game.

# Reflection
This week made me feel like a "real" programmer. Running a script from the terminal feels much more professional than just typing lines into a shell.

# Week 6 – Lists & Tuples

# What I Learned
I learned how to handle collections of data. 
Lists are great because you can change them (add or remove items), while Tuples are fixed (immutable). 
I also learned how to "slice" lists to get exactly the piece of data I want.

# Practical Work
Made a shopping list program where I could add items and sort them alphabetically.
Experimented with tuples to store things that should never change, like my birthday.

# Reflection
Managing one variable is easy, but managing a hundred is impossible without lists. Slicing was a bit confusing at first, but it’s a total game-changer for organizing data.

# Week 7 – Sets & Dictionaries

# What I Learned
This week was about more advanced ways to store data. 
I learned about Dictionaries, which use "Keys" and "Values" (like a real dictionary), and Sets, which are perfect for when you want to make sure there are no duplicates in your data.

# Practical Work
Created a dictionary to store contact info, where the name is the "key" and the phone number is the "value."
Used a set to quickly filter out duplicate names from a long list.

# Reflection
Dictionaries are probably the most useful thing I’ve learned so far. Being able to look up a value by a name instead of an index number makes the code much more readable.

# Week 8 – Reading & Writing Files (I/O)

# What I Learned
The final piece! I learned how to make my data "stick" by saving it to files. We covered how to open, read, write, and close files safely using the with statement so we don't crash anything.

# Practical Work
Wrote a script that takes a user's journal entry and saves it to a .txt file on my computer.
Created a program that reads that file back and prints it to the console.

# Reflection
It’s a great feeling to know that when I turn off my computer, my data doesn't just vanish. File handling makes my programs feel like they have a long-term memory.
